# seu-campus-guide 1.2.0 交接说明

给接手修改和上传的同学。整理日期 2026-09-05。

## 这个包是什么

东南大学六校区（四牌楼／九龙湖／丁家桥／江北／苏州／无锡）校园生活问答 Skill，
159 个 Markdown 文件，660 KB，无二进制。

**核心设计：每条资料都带来源和年份。** 四牌楼是 2026.08 图片核对版，其余校区多为 2025 版。
来源冲突处并列两种口径，不硬选一个数字。不假装有实时状态。

## 压缩包里有什么

**这个包是自包含的**，解压后不需要任何其他文件就能重建（已在干净解压副本里实测跑通 `build_all.sh`）。

| 顶层目录 | 作用 |
|---|---|
| `skillhub-release/` | 发布包、构建脚本、审计记录（下面细说） |
| `SEUCampusGuidance/原校区指南-wiki/` | 五校区 2025 版正文，`build_release.py` 的输入 |
| `SEUCampusGuidance/knowledge-base/` | 建筑・部门・办事的结构化条目，导出成 `references/official/` |
| `seu-campus-guide/` | **上一版 1.1.0 的 Skill**，是通用页的输入，别和发布包搞混 |
| `2026四牌楼/` | 15 张 2026.08 原图，改四牌楼内容时对着核 |

⚠️ 顶层的 `seu-campus-guide/` 是**旧版输入**；要上传的是
`skillhub-release/seu-campus-guide/`。两者同名，注意别搞反。

`skillhub-release/` 内部：

| 路径 | 说明 |
|---|---|
| `seu-campus-guide/` | **发布包本体**，上传的就是这个目录 |
| `work/` | 构建脚本与审计记录，**不随包分发** |
| `来源与更新对照表.md` | 303 条来源决策（哪段进了、哪段被替换、为什么） |
| `验证记录.md` | 结构检查与走查结果，以及明确的验证限制 |

发布包内部：

- `SKILL.md` — 入口，含 frontmatter、查阅流程、澄清规则、边界
- `OUTPUT-CARDS.md` — 六类回答卡片模板（只定义结构，不存事实）
- `references/index.md` — 主题索引，只做导航
- `references/common/` — 15 个跨校区通用页
- `references/campuses/<校区>/` — 六校区专页
- `references/official/` — 52 个建筑・部门・办事条目
- `references/sources.md` — 来源、版权、日期口径
- `references/conflicts.md` — **未解决冲突清单，改内容前先看这个**

## 怎么改

**不要直接改 `seu-campus-guide/` 下的文件——它是生成物，重建会被覆盖。**

内容改在这两处：

- `work/curate_content.py` — 四牌楼各页、江北 2026 补充页的正文
- `work/build_entry.py` — SKILL.md、OUTPUT-CARDS.md、sources.md、conflicts.md

改完重建：

```bash
sh work/build_all.sh
```

脚本会清空并重建发布包，跑一遍 skill-creator 的校验器。

其余五校区的正文来自上级目录的 `SEUCampusGuidance/原校区指南-wiki/`，
`build_release.py` 负责搬运和加边界声明；要改那些得动原 wiki 或 `build_release.py` 的映射表。

## 改完自查

```bash
# 断链 + 可达性
python3 - <<'PY'
import re,os
from pathlib import Path
root=Path('seu-campus-guide'); bad=[];n=0
for p in root.rglob('*.md'):
    for m in re.finditer(r'\[([^\]]*)\]\(([^)]+)\)',p.read_text()):
        t=m.group(2)
        if t.startswith(('http','#','mailto')):continue
        t=t.split('#')[0]
        if not t:continue
        n+=1
        if not (p.parent/t).resolve().exists():bad.append((str(p),t))
print(f'内部链接 {n} / 断链 {len(bad)}')
for b in bad:print(' ',b)
PY
```

上次通过的基线：**159 个 md，613 条内部链接，0 断链，159/159 可达**。

## 怎么上传

用 `redskillhub-upload` CLI（npm 包）。装的时候用用户可写目录，别 sudo：

```bash
export NPM_CONFIG_PREFIX="$HOME/.npm-global-redskillhub"
export NPM_CONFIG_CACHE="$HOME/.npm-cache-redskillhub"
export PATH="$NPM_CONFIG_PREFIX/bin:$PATH"
npm install --global redskillhub-upload
```

先 dry-run 看载荷，确认无误再提交：

```bash
redskillhub-upload tags          # 拉实时标签
redskillhub-upload publish <绝对路径> --dry-run --agent --source original --tag 学习成长
printf 'submit\n' | redskillhub-upload publish <绝对路径> --agent --source original --tag 学习成长
```

上次 dry-run 的实测结果（2026-09-05，CLI 1.0.2）：

| 字段 | 值 |
|---|---|
| `skill_identifier` | `seu-campus-guide`（自动派生，提交后跨版本**不可改**） |
| `version` | `1.2.0`（CLI 读的是 frontmatter 的 `metadata.version`） |
| `name` | `seu-campus-guide`（**中文 `display_name` 不会被采用**） |
| 打包体积 | 215,757 字节 |

## 三件必须知道的事

**1. source 字段还没定。** 上次 dry-run 填的是 `original`（原创），但包里整合了地理协会
《新生实用信息简明指南》六校区内容，许可是 **CC-BY-SA 4.0**。严格说这是演绎作品，
ShareAlike 要求沿用同一许可。正式发布前请确认：是标 `--source repost`（`repost_source`
填地理协会／东奔南走），还是把 `SKILL.md` 的 `license` 明确写成 CC-BY-SA 4.0。
计划是用东奔南走账号发布，那种情况下口径可能不同，但这个字段得有人拍板。

**2. 只有四牌楼吃到了 2026 更新。** 九龙湖、丁家桥、苏州、无锡仍是各自来源年份的历史资料，
`official/` 沿用原库核验日期 2026-08-17／18。页面上都印了版本，别当成统一年份的数据。

**3. 医保关键流程未核验完。** 校医院 2026-08-27 发布的医保／异地就医／零星报销三份须知，
正文一直访问不到，保障期、比例、限额、材料都没确认。见 `conflicts.md`。

## frontmatter 的坑

skill-creator 校验器只允许这 6 个顶层键：
`name`、`description`、`license`、`allowed-tools`、`metadata`、`compatibility`。

上一版 1.1.0 有顶层 `version` 和 `agent_created`，**会直接校验失败**。`version` 必须放进 `metadata`。
`name` 必须 kebab-case，`description` 不能含尖括号且不超过 1024 字符。
