# 回答卡片规范

模板只定义**信息结构**。时间、电话、地点、价格一律从 `references/` 对应页面取值，
本文件不保存任何校园事实。

## 总则

1. 先给一句话结论，再决定要不要用卡。
2. **每次最多 1—2 张卡**。简单问题（一个电话、一个地点、是否可以）直接一两句话答完，不套卡。
3. 卡里每个字段都要有来源。**缺字段就省略或写"资料未提供"，不要为了填满卡片推测。**
4. 标出资料版本（如"四牌楼 2026.08 指南""九龙湖 2025 版"），时间/电话/班次类再加一句以当期通知为准。
5. 来源之间有冲突时，把两种口径都列出来并说明各自出处，不要静默选一个。
6. **出处只能写两种东西**：(a) 你实际读过的本包页面，写页面路径或页名；
   (b) 该页面正文里**逐字存在**的 URL。
   **绝不允许**：凭记忆写 URL、把上一轮问答里的链接搬过来、给页名配一个自己拼的网址。
   拿不准就只写页名，不带链接——少一个链接远好过给一个指错地方的链接。
7. **紧急求助先给行动指引**，卡片和澄清都往后放。
8. 输出是 Markdown 纯文本，不承诺平台原生交互组件。

## 窄屏适配

- 表格最多 3 列。超过 3 列改成纵向步骤或短列表。
- 时刻表、路线这类长表，只列用户问到的那几行，其余给出处让其自查。
- 不用横向长链条排版（`A → B → C → D → E`），改成分行的编号步骤。

## 六类卡片

### A 行程卡 — 怎么从这里到那里、一天的动线

```
**{起点} → {终点}**（{资料版本}）
1. {步骤}｜{耗时/班次，未提供则省略}
2. {步骤}｜{耗时}
3. {步骤}
提示：{换乘、末班、门禁等限制}
出处：{页面路径}｛该页有 URL 时才附，且必须是页内原文的 URL｝
```

### B 办事步骤卡 — 报修、补卡、借书、缴费、报销

```
**{事项}**（{适用人群／校区}）
材料：{清单，未提供则写"资料未提供"}
1. {步骤}
2. {步骤}
3. {步骤}
地点／入口：{窗口或线上入口}
出处：{页面路径}｜{以当期通知为准的提醒}
```

### C 设施卡 — 某栋楼／某片区域有什么

```
**{地点}**（{资料版本}）
| 设施 | 位置 |
|---|---|
| {设施} | {位置} |
说明：{通行、开放限制}
出处：{页面}
```

### D 电话卡 — 找谁、打哪个号

```
**{场景}**
| 用途 | 号码 |
|---|---|
| {用途} | {号码} |
{号码有来源差异时，在此列出两种口径及各自出处}
出处：{页面}
```

紧急场景先写"先打 120／119／110 并说明准确位置"，校内号码放在其后，不用校内号码替代国家紧急求助渠道。

### E 校区对照卡 — 同一件事各校区不同

```
**{事项}各校区差异**
| 校区 | {关键字段} | 资料版本 |
|---|---|---|
| {校区} | {取值／资料未提供} | {版本} |
说明：{不可互相套用的边界}
出处：{各页面}
```

只列用户涉及的校区，不必六个都填。某校区资料缺失就写"本包未覆盖"，不要用别的校区补。

### F 数据卡 — 时刻、价格、营业时段

```
**{数据主题}**（{来源}，{发布或版本日期}）
| {维度} | {取值} |
|---|---|
| {行} | {值} |
边界：{适用日期、人群、是否为历史版本}
出处：{页面路径}｛页内原文 URL，没有就不写｝
```

数据卡必须写清楚是哪个版本的数据，且不得表述成当前状态。

## 反例

- ❌ 用户已经说了"我在九龙湖"，还反问"请问您在哪个校区？"
- ❌ 把某校区的图书馆时间当作全校答案。
- ❌ 两个来源时间不同，直接选一个报出去。
- ❌ 为了凑满模板，给没有资料的字段编一个耗时或价格。
- ❌ 一次甩四张卡；或简单问题也套卡。
- ❌ 把 2025 版的班次表说成"现在的班次"。
- ❌ **给出处配一个页面里不存在的 URL**，或把上一个问题引用过的链接挪到这个答案上。
  出处指错地方比不给出处更有害——它看起来可信。
